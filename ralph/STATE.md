### Roadmap P0.1 step 3 — Echo-aware voice barge-in — 2026-09-29
New opt-in `conversation.voiceBargeIn` (Settings → Conversation mode checkbox, default off): the user can interrupt ARIA by talking over it, with no wake word. `AriaAudio.EchoAwareBargeDetector` compares each 20 ms mic frame against what ARIA is emitting (TTS analyser RMS × volume): peak-held reference (≈120 ms, covers output latency and reverb), speaker→mic coupling learned as a running ≈85th percentile, a 5-of-10-frame vote (speech over echo is interleaved, not continuous), and a 500 ms learning warm-up that persists across replies. On fire it latches until playback ends and opens a hands-free utterance with a ≤320 ms PCM pre-roll so the first syllables survive.
Verification: red-first synthetic tests in smoke-audio. `smoke:barge-in` uses real Piper speech through a simulated room (60 ms latency, 3-tap reverb, noise): echo alone never fires at speaker gains 0.3–1.6; the user interrupts in 80–140 ms when ≥ ~4 dB above the echo. Measured limit: at echo 0.9–1.2 a user at or below echo level is missed or takes >500 ms — energy-only detection cannot separate them, which is why it is opt-in. `smoke:barge-live` boots the built app with a fake capture device, pauses inside `checkVoiceBargeIn` on a real mic frame over CDP, and proves: Settings save, echo ignored, a single fire with pre-roll, and no fire when idle or disabled. It caught a real bug — the detector re-fired 4× before the async `beginUtterance` set `listening` — now latched.
Not yet done: test with a real mic and speakers (false-interrupt rate per 10 minutes of playback); the pre-roll can include up to 320 ms of ARIA echo; a true AEC or reference-correlation detector is the upgrade path.

### Roadmap P0.1 step 1 — Speculative early endpointing — 2026-09-29 (uncommitted)
Hands-free turns previously always waited the fixed 850 ms trailing-silence hang before STT even started.
